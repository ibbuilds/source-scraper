# Source Scraper v0.14.0 Beta 1 — real public-source acceptance and HTTPS fix

The main product is still a local, source-independent, JSON/NDJSON-first CLI. Obsidian remains an optional integration. There is **no authenticated X For You connector** in this release.

## A real-world end-to-end test, not just synthetic fixtures

This release adds an executable example querying the **documented, public npm registry search API** for React/UI packages. Its `public-json` source adapter maps actual search results into typed observations, normalizes and deduplicates them, preserves origin, persists them to SQLite and exports schema-versioned JSON.

The live [GitHub Actions acceptance run #40139687116](https://github.com/ibbuilds/source-scraper/actions/runs/40139687116) retrieved **8 actual packages**, persisted 8 distinct entities, validated JSON v1 provenance and verified that an explicit human review survived a fully offline re-evaluation. It did **not** use private credentials, access a personal Obsidian vault, or send webhooks.

Run the example with the standalone CLI (Node 22.16+):

```sh
node source-scraper.mjs run --config examples/npm-react-ui/project.json --db ./npm-research.sqlite
node source-scraper.mjs query --config examples/npm-react-ui/project.json --db ./npm-research.sqlite
node source-scraper.mjs export --config examples/npm-react-ui/project.json --db ./npm-research.sqlite --out ./npm-research.json
```

The manifest comes from `examples/npm-react-ui/project.json` in a source checkout, or copy it to your own workspace and provide that path. For an entirely offline synthetic demo, use `node source-scraper.mjs init --dir ./demo`.

## Important HTTPS correctness fix

The first live run exposed a real networking bug missed by mocked HTTP tests: the DNS-pinned public HTTP transport returned a scalar IP address even when Node.js requested the `{all:true}` lookup callback shape. The real TLS connection failed with `Invalid IP address: undefined`. The lookup callback now returns a **single pinned, already DNS-validated address in the correct shape for both singular and all-address lookups**, without weakening rejection of private/local DNS, HTTPS downgrade redirects or unsupported X hosts.

Regression tests now explicitly invoke both Node DNS callback modes. The public HTTP user agent identifies Source Scraper instead of the historical Obsidian-specific plugin name.

## Regression and automation

- Cross-platform unit, packaging and persisted-state smoke tests on Linux, macOS and Windows.
- Real Obsidian Desktop E2E in an isolated synthetic vault, separately from the CLI.
- Read-only live npm acceptance runs on relevant PR/main changes and weekly. A real upstream outage or changed payload yields a **visible failed run**, not an empty false-positive success. It is intentionally distinct from deterministic CI.
- The GitHub Release publisher first builds and verifies the new tag and three complete assets, then removes the previous public release. Historic Git tags/commits stay intact.

## Assets

- **`source-scraper.mjs`** — main, self-contained executable for Node.js 22.16+.
- **`source-scraper-0.14.0.tgz`** — locally installable npm tarball (**not published to the npm registry**).
- **`obsidian-x-feed-scraper.zip`** — optional Obsidian plugin, retaining `x-feed-scraper` ID.

## Outstanding blockers

- The official X API's reverse-chronological Following home timeline is **not equivalent** to the account's personalized algorithmic **For You** recommendations. No verified provider-authorized API or user consent for that specific feed has been established. No extracted X cookies/session tokens or undocumented scraping path was introduced.
- The owner's actual Obsidian/MCP connection returned **HTTP 429** during this verification, so personal vault install, backup, note protection and reference-library acceptance remain unverified. The synthetic real-Obsidian CI vault is not a substitute.
- A successful npm source import does not independently prove package license authenticity, source relevance, verified official GitHub repository links or compatibility for every data source.
- The repository's GitHub About description must be set by a repository admin; the connected tool here does not expose repository metadata updates.
