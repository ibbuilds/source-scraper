# Source Scraper 0.16.0 — independent topic and source workflows

Post relevance, linked-resource relevance and resource quality are separate.
The generic engine retains unlinked observations, exposes versioned topic evidence
and durable pertinent/irrelevant/uncertain decisions, and preserves explicit human
decisions over agent decisions. No model, paid API or domain vocabulary is added.

- Saved score floors now apply to queries, exports and resource batches. Current
  AI discards leave ordinary results; explicit human Keep stays authoritative.
- Public enrichment has a durable queue and bounded backoff. `process-pending`
  continues it without another source read or changing observation timestamps.
- X connections share a global window budget. Typed temporary failures and
  preserved checkpoints allow the client to resume bounded work.
- `topic-batch` supports both observations and resources. Whole-post visual
  evidence and exact fingerprints are required for positive post decisions.
- Post feedback can use an unlinked post, but requires a current private decision,
  exact live snapshot, minimum observed engagement, existing local like grant,
  enabled feedback and an in-progress journal entry. Existing target allowlists
  remain in force. No real likes were part of release testing.
- JSON entity schema remains v1; SQLite changes are additive. Existing reviews,
  observations and checkpoints remain readable. Use with Obsidian plugin 1.2.0.

See [topic evidence and calibration](../topic-relevance.md). Synthetic tests
exercise contracts and failure paths; they do not establish semantic accuracy.
Real source acceptance on the existing local session returned one page, 28 posts
and three new resources. That sample does not guarantee future session access or
complete coverage of X.
